03 / THE WORKFLOW

九个阶段，把信息变成证据。

查看执行计划 ↗

Python 做可重复的计算，角色代理做需要理解文本的判断。每一步都保存文件，再通过三个检查关卡。点击阶段查看输入、处理和交付内容。

文件，是代理之间的交接协议。

采集器输出 JSONL；标签代理读写批次 JSON；整理脚本写 SQLite；分析代理记录矩阵判断；审计代理保留检查结果。主会话按 STATUS.md 恢复进度。

可以并行，也必须有边界。

两类来源采集可并行，标签按批次处理，公司调研可与标签和图谱阶段并行。矩阵之后必须审计，审计之后才生成最终报告。

为什么原始目标是 50–100 篇，最后却有 267 / 284 篇？

关卡 A 规定：相关性评分 2 或 3 超过 200 条时，仅保留评分 3 作为核心集。它没有进一步规定硬上限，所以第一轮去重后仍有 267 篇，第二轮有 284 篇。是否接受扩大的样本，仍是团队决策。

运行花了多久，费用是多少？

项目日志记载：第一轮完整流程耗时约 3 小时 55 分钟，调用子代理 53 次；OpenAlex 用量费用为 0.0404 美元（报告约写为 0.04 美元）。后续审计修复另有工作量，不能包含在首次运行数字中。第二轮新增采集阶段记录 0.01 美元，不是第二轮总成本。

以上是历史日志记载，不是当前报价，也不包括模型推理、人工或所有运行成本；按阶段费用记录仍需补全。

05 / TRUST & LIMITATIONS

有证据，比看起来完整更重要。

一次值得说明的失败

测试通过，
也可能只是迎合了测试。

第 2 轮审计时，矩阵构建程序导入了审计检查函数，并向 18 个类别单元格填入引文词语。审计通过了；真正指出循环验证问题的是独立的第二评审代理。

之后拆分构建与审计，用简洁标签重建矩阵，并换随机种子重新抽查。

同属第一轮研究的审计历史；不是三次独立采集运行。

A

相关性与规模

评分 2 / 3 的记录目标为 60–200 条；超出则只保留评分 3，低于则扩大检索并重试。

防止无关文献淹没结果
B

标签与原文

核心论文全部有路线和成熟度标签；至少 90% 的证据句必须是摘要的逐字子串。

防止标签失去文本依据
C

复取与抽查

09 / QUESTIONS TO EXPECT

汇报时，准备好回答这些问题。

这和普通文献综述有什么区别？

除结论外，还保存采集配置、原始数据、结构化标签、证据片段、比较矩阵、关系图谱和审计日志。价值在于可复算与可追溯，但文本判断仍需要人工复核。

你个人做了什么？是不是整个研究都是你完成的？

已记录的个人贡献是中文 README、贡献日志和本次展示网站。采集、分析和审计属于项目已有成果。其他研究贡献需要补充真实记录，不能仅凭参与项目就推断全部工作由我完成。

为什么不直接说哪条路线最好？

样本数量受检索策略影响，技术参数又可能来自不同器件、端口规模、实验条件和设计目标。当前矩阵支持提出问题与定位证据，还不能代替统一条件下的工程选型。

第二轮是不是已经结束？

没有。发布的 run2 快照完成到图谱阶段；公司表沿用第一轮，矩阵、审计和最终报告仍待重做。第二轮的 284 篇核心论文不能直接套用第一轮的审计通过率。

为什么 README 还写 run2 没推送？

该 README 文案落后于实际分支。2026-09-26 已获取 run2 提交 3859702，并按其 STATUS.md 展示进展。历史文件名 audit_run2_* 指第一轮审计修复，与这次 arXiv 扩展运行不是一回事。

目前最大的风险是什么？

采样偏差、作者拆分、摘要覆盖不足，以及类别结论的证据标准不一致。通过自动检查不能消除这些风险；独立审计、全文阅读和明确范围仍有必要。

下一步最有价值的工作是什么？

先完成第二轮矩阵、独立审计和报告，再补关键种子论文和作者消歧。对我个人，持续同步中文文档和可信的状态说明，是明确、可验证的下一项贡献。

网站里的数字如何保持可信？

数据来自锁定的两个 Git 提交，由 build_site_data.py 读取数据库和 CSV 构建，链接指向对应版本。页面显示的是快照，不是实时监控。更新时必须同时核查数据、状态、说明文字和来源。
